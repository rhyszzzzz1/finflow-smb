Introduction

Nepalese SMEs often juggle spreadsheets for stock and informal ledgers for finance. FinTrac targets integrated order-to-cash, procure-to-pay, and double-entry posting in one web stack (finflow-smb + finflow-backend + MySQL), scoped per business profile.

Academic questions

How can a single web system improve consistency and auditability for SMEs versus disconnected tools? Sub-questions: Can document lifecycles (draft → approve → post) align inventory with GL? Can reconciliations tie subledgers to control accounts?

Literature review

Academic and industry sources converge on cloud accounting adoption (usefulness, cost, trust, regulatory readiness), inventory–GL integration for accurate COGS and planning, receivables and liquidity risk, security perception as an adoption barrier, and usability / CSV migration from spreadsheets. FinTrac is positioned as an integrated O2C/P2P + inventory + settlements prototype that speaks directly to those gaps.

Overview

FinTrac (branded in the React UI; repository finflow-smb) is a browser-based business suite for small and medium enterprises. It replaces ad-hoc spreadsheets for sales and purchasing cycles with document-driven workflows, a MySQL data store, and double-entry journals generated when operational documents post. Tenancy is rooted in authenticated profiles (each business user / company scope), with optional migration toward a separate companies entity where present.

  • Frontend: React (TypeScript), Vite, React Router, TanStack Query, shadcn-style UI components.
  • Backend: Node.js, Express 5, mysql2 (promise pool + legacy callback connection), JWT sessions, bcrypt password hashing.
  • Compliance-style onboarding: KYC document upload; kyc_status gate; separate admin portal for review.
  • Signup security: Email OTP via pending_signups when SMTP/Gmail is configured (bypassed for direct DB seed accounts in development).

Aims & academic question

Aims

  • Unify commercial documents (quotes through invoices, POs through bills) with stock and GL impact.
  • Give SMEs AR/AP aging, trial balance / P&L / balance sheet, and reconciliation views over subledgers.
  • Support inter-business relationships (buyer/seller invites) on a shared platform.

Academic question

How can a single integrated web system improve data consistency and auditability for Nepalese-style SMEs compared to disconnected inventory spreadsheets and manual ledger books — while remaining usable without an enterprise ERP team?

Objectives (mapped to implemented modules)

  • Sales: Quotes → Orders → Invoices → Credit notes; optional approval before posting.
  • Procurement: Purchase orders → Goods receipts (stock / GRNI) → Purchase bills → Debit notes.
  • Inventory: items, warehouses, stock_movements; weighted-average costing; COGS on posted stock sales.
  • Finance: chart_of_accounts, journal_entries, tax_codes (e.g. VAT), settlements / payment allocation.
  • Reporting: Trial balance, P&L, balance sheet, AR/AP aging, stock summary, customer/vendor statements, reconciliation bundle (AR, AP, inventory, tax, advances, GRNI).

Core user flows (accurate to services)

Order-to-cash (sales)

Sales quote (draft) → Sales order (e.g. convert from quote) → Sales invoice (draft) → submit for approval → approve → POST → journal: revenue, AR, output VAT (via tax service) → stock: sale_issue movements + COGS / inventory lines when lines reference stocked items

Procure-to-pay

Purchase order → Goods receipt (posted) → stock / GRNI per line accounting → Purchase bill (match receipt where applicable) → POST → AP, purchases/expense, input VAT; avoids duplicate receipt when billed from GR

Settlements

Payments (incoming/outgoing) + allocations to invoices/bills; customer/vendor advances when overpaid.

Literature review — thematic synthesis & FinTrac positioning

The written review synthesises SME-focused work on cloud accounting adoption (e.g. usefulness, cost, vendor trust, regulatory awareness — Alshamaila et al. 2013; Mujalli 2024; OECD 2022), inventory linked to the general ledger (Romney & Steinbart 2017; Liang & Wu 2019), receivables and liquidity (Atradius 2023; Rawashdeh 2023), security and trust (Nagahawatta 2021; Chen & Zhu 2020), and onboarding from spreadsheets (Square 2022; Cin7 2022; Papa et al. 2018). FinTrac implements an operational + financial web stack that responds to those themes; the table below maps literature themes to this artifact (full Harvard references in the thesis chapter).

Topic Comparison / insight
Cloud adoption & barriers Literature links uptake to perceived benefits but also to trust, security perception, and digital maturity. FinTrac is a low-infrastructure, browser-based prototype aimed at reducing adoption friction for SME-style workflows.
Inventory–accounting integration Studies tie automated stock–ledger flows to accuracy and purchasing efficiency. FinTrac posts inventory movements from sales, credit notes, goods receipts, and bills into a coherent ledger alongside double-entry journals.
Receivables & cash visibility Industry and survey work highlight late payment and weak monitoring as liquidity risks; cloud accounting can improve recovery metrics. FinTrac supports invoice / settlement flows, ageing-style reporting, and financial dashboards grounded in posted data.
Security, usability, CSV Security concerns suppress adoption unless controls are visible; CSV / structured import and simple UX ease migration off spreadsheets. The stack uses JWT auth, tenant-scoped APIs, and CSV-capable paths aligned with the full review’s recommendations.

Evaluation / reflection

Building FinTrac required reconciling legacy tables (inventory, clients, vendors) with modern items/stock_movements and canonical counterparties. The most demanding work was transactional posting (rollback on inventory or account-resolution failure) and keeping document sequences and journal entry numbers unique per tenant. The project strengthened skills in full-stack design, schema migration under live routes, and test-driven regression for accounting invariants.

Conclusion

FinTrac delivers a coherent SME workflow from commercial documents through to posted journals, tax transactions, and management reports, with inventory tied to sales and procurement events. It demonstrates how a focused web architecture (React + Express + MySQL) can improve traceability for smaller businesses without adopting a full multinational ERP.

Future scope

  • Multi-user roles per company and stricter maker–checker on approvals.
  • CSV / Excel import–export for items, stock movements, and opening balances.
  • Bank statement import, payroll, and richer mobile / offline use.
  • Stronger tenant isolation and optional marketplace integrations.
